# 框架设计（建模前的顶层设计）

> 写代码之前先想清楚的四件事。这份文档解释了"为什么最后长成这个样子"。

---

## ① 一句话核心思想

**这是一个"时间维度搬运"问题：把能等的算力从贵的时段搬到便宜/干净的时段，把能存的电从有光的时段搬到没光的时段。**

题目里的三句话——电价变、需求变、供给变——其实是同一个矛盾的三面：
**最便宜的时刻、需求最高的时刻、最干净的时刻，互不重合。**

所以整道题只有一个杠杆：**时间**。空间维度（把任务送到别的数据中心）我们主动放弃，
因为题目没给，加了会变成另一个问题。

## ② 核心量（只有三个）

| 量 | 一句话定义 | 单位 |
|---|---|---|
| $x_t$ | 第 $t$ 个 15 分钟跑多少**可延迟算力** | MW |
| $g_t$ | 第 $t$ 个 15 分钟从电网**买多少电** | MW |
| $E_t$ | 第 $t$ 个 15 分钟末**电池里有多少电** | MWh |

其余全是它们的函数。**决策 = 这三个量的时间序列。**

## ③ 赛题五问 → 建模动作映射

赛题第 2 节列了五个问题，它们不是论文的五章，而是**五个必须被模型结构回答的问题**：

| 赛题问题 | 建模动作 | 产物 |
|---|---|---|
| 怎么定义"好"？ | 定 4 个指标：钱 / 碳 / 峰值 / SLA，并给出可比的度电指标 | 指标表 + `summary.csv` |
| 比不调度好多少？ | 构造"不调度"基准（算力均匀摊平 + 电池闲置），跑同一套模型 | `fig3_compare.png` |
| 凭什么信它接近最优？ | 对偶界 + 双算法 + **小规模全枚举** + 独立贪心 | `verify.py` 11 项 |
| 条件变了还成立吗？ | 敏感性扫描 + 蒙特卡洛 + 三个场景（A/B/C） | `fig5`、`fig6`、场景表 |
| 假设合理吗？错了怎样？ | 假设分级 [强]/[弱]，逐个说明反转后果 | 报告 Q5 表 |

**这张表决定了模型的形态**：

- 要回答"定义好" → 目标函数必须可分解（钱、碳分别可调），所以用加权和而不是单一目标；
- 要回答"好多少" → 必须有基准，所以模型要支持"关掉某个决策"（`shift=False`、`battery=False`）；
- 要回答"接近最优" → 必须能穷举验证，所以选了 LP 而不是启发式/强化学习；
- 要回答"条件变了" → 所有参数必须能从外部传入（`build_instance(**overrides)`）；
- 要回答"假设错了" → 必须能一键切换碳强度曲线（`carbon24=`），否则没法验证最弱的假设。

## ④ 命题树（两层）

```
"能不能更便宜、更绿地跑 AI 数据中心？"
│
├─ P1  便宜和干净在时间上是错配的吗？
│     └─ 证据：图 1(b)，谷段最便宜也最脏；"又便宜又干净"的格子是空的
│
├─ P2  只按价格调度，能同时省钱和减碳吗？
│     └─ 不能。省 30.5%，但碳 +2.8%  ← 【核心反直觉结论】
│
├─ P3  储能能把不匹配补上吗？
│     └─ 能补钱，不能补碳。净增 62 kg/MWh，且随容量增大而恶化
│
├─ P4  那什么才有用？
│     ├─ 碳价：几乎无用（要 2000 元/t 才改变排班）
│     └─ 光伏：有用（12 MW 起双赢，16 MW 时 −50.8% 钱 / −25.7% 碳）
│
└─ P5  这个结论稳定吗？
      ├─ 光伏预测误差 ±15%：200 次全为正，最差仍省 27.6%
      ├─ 夜间电网变干净（430 kg/MWh）：结论反转，减碳 +14.2%
      └─ 截止期收到 12:00：无解 —— 说明了方法的物理边界
```

**P1 是前提，P2 是发现，P3 是排除错误答案，P4 是给出正确答案，P5 是划定适用范围。**

## ⑤ 一开始想错了什么

| 最初的想法 | 为什么放弃 |
|---|---|
| 用 MILP 把每个训练作业当整数变量 | 96 时段 × 多作业会爆；单日收益提升 <2%，性价比低 |
| 用强化学习做"智能调度" | 不可解释，且没有仿真环境；评委问"为什么这么排"答不上来 |
| 把"绿色"定义成碳排最小 | 会得到一个电费涨 12% 的方案，现实中没人会执行 |
| 假设"储能必然减碳" | 数据不支持，这是本项目最有价值的否定结论 |
| 把需量电费直接放进主模型 | 单日模型算不出月峰值，会系统性高估。改成单独的扩展实验 |

---

## ⑥ 交付边界

**做**：单日、确定性、单站点、能量层面的调度。
**不做**：跨地域负载迁移、作业级整数排程、实时滚动优化、碳捕集/绿证交易。

边界写清楚，比假装什么都能做强。
